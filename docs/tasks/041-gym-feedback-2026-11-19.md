## Outcome / acceptance
1. A substituted exercise does not show the replaced exercise's planned load (card Plan row and
   Up next line). Sets, reps and RIR of the slot still show.
2. Tapping Upload shows what the app is doing until it ends: "Uploading…", the current sync step
   and a step bar. "Upload pending / Retry upload" appears only when an upload did not finish.
3. The finished-workout footer is full width in every state (finished, uploading, pending,
   uploaded, conflict); button pairs share the width evenly.
4. Owner request: correct an exercise name in the catalog.

step reporting (no change to sync order or conflict logic), `scripts/repknot rename-exercise`.

## Decisions / discoveries
- Cause of #3: the footer's inner column had no full width, so whenever no full-width button was
  present (pending, uploaded) it shrank to its content and sat at the start.
- Upload is slow because it is a full refresh (program, all sessions, check-ins, coach notes)
  before the push. Order kept (refresh-then-push is the conflict basis); only reported now.
  A faster push-first path would be sync logic: separate decision if wanted.
- Past sessions keep the exercise name they were logged with (`session_exercises.exercise_name`
  is "name at the time"); the catalog rename affects pickers and new workouts only. Rewriting old
  snapshots would edit retained real data: owner decision, not done.
- During upload, Resume and Discard are hidden so they cannot race the push; Done stays.
